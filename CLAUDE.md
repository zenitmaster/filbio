# FilBio

Static, client-only paternity/maternity calculator from STR profiles. Next.js App Router
with `output: "export"`, TypeScript, Tailwind CSS v4, Zustand, Vitest.

## Commands

- `npm run dev` / `npm run build` (static site in `out/`) / `npm run lint`
- `npm test` runs Vitest once; `npm run test:watch` watches.

## Invariants

- **No network, ever.** Genetic profiles are sensitive personal data. No API routes, no
  analytics, no CDN assets, no third-party requests. The CSP in `src/app/layout.tsx` and
  `vercel.json` enforces it; do not loosen it. State lives in `localStorage` only.
- **`reference/` is git-ignored and must stay so.** It holds a laboratory's private
  workbook, which may contain case data. Never commit it, quote genotypes from it, or put
  laboratory or personal names in tracked files. Test data must be invented.
- **The engine is the product.** `src/lib/genetics/` is pure and fully tested. Any change to
  a formula needs a test whose expected value was derived independently (by hand or in
  another language), never copied from the engine's own output.
- Never display a probability of parentage as 100 %: use `formatProbabilityPercent`.
- Bundled allele frequencies are generated by `scripts/build_population_data.py`; do not
  edit `src/data/populations/*.json` by hand, and never invent frequency data.

## Conventions

- UI strings live in `src/lib/i18n/es.ts` (source of truth for keys) and `en.ts`. Spanish is
  the default language. Counted messages come in `.one` / `.other` pairs, used via `plural()`.
- Colours are semantic tokens in `src/app/globals.css` (`bg-surface`, `text-ink`, ...).
  Inclusion and exclusion are deliberately not green/red: both are valid results. Amber
  (`attention`) is for what needs the analyst's eye. Dye colours are for data only.
- A scroll wrapper around a table must be `relative`, or `sr-only` labels inside it widen
  the page.
